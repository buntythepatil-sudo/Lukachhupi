# Security Specification — Gully Chhupan Chhupai 1995 Profiles, Friends, Rooms & Safety

## 1. Data Invariants
1. **PII & Stats Tamper Isolation**: `/users/{userId}`, `/users/{userId}/privacy/{docId}`, and `/users/{userId}/blocked/{blockedId}` are strictly restricted to `isOwner(userId)` (`allow list: if false` on `/users`, `/privacy`, and `/presence`). Newly created `/users/{userId}` documents MUST start with zeroed progression (`matchesPlayed == 0`, `matchesWon == 0`, `unlockedLevel == 1`, `levelStars == {}`), and client updates to `/users/{userId}` are strictly restricted to `['username', 'avatarId', 'updatedAt']` — players CANNOT modify their own wins, stars, or unlocked levels.
2. **Presence Isolation for Strangers**: `/users/{userId}/presence/status` is readable (`get` only) strictly by the owner or confirmed friends (`isFriend(userId, request.auth.uid)`). When `hideProfileFromStrangers` is enabled, `/playerDirectory/{userId}` publishes `isOnline: false` and `avatarId: 'private'`.
3. **Friend Request & Room Invite Policy Enforcement**: `/friendRequests/{requestId}` creation verifies via `get(/playerDirectory/{toUid})` that `friendRequestPolicy != 'nobody'` and `!isBlockedEitherWay`. `/roomInvites/{inviteId}` creation and sender updates verify `isFriend(toUid, fromUid)`, `!isBlockedEitherWay`, and `roomInvitePolicy != 'nobody'`.
4. **Searchable Directory Bounds**: `/playerDirectory/{userId}` stores only non-PII public handle fields. `list` queries require verified authentication, bounded `request.query.limit <= 15`, and type validation on `resource.data`.
5. **Atomic Friendship Consent & Terminal State Lock**: Creating a friend edge requires an active pending `friendRequests/{fromUid}__{toUid}` transitioning atomically via `getAfter(...)` to `status == 'accepted'`, with both reciprocal edges created in the same batch and zero block entries in either direction. Once `'accepted'` or `'declined'`, a friend request cannot be modified again.
6. **Multiplayer Room Member Isolation**: `/rooms/{roomId}` and `/rooms/{roomId}/members/{memberId}` enforce host-and-member isolation. Only the host or a verified member present in `/rooms/{roomId}/members/{uid}` can read the room or its member list; non-members are denied reads, writes, and uninvited joins (joining requires a valid `roomInvites` from the host and zero block entries).
7. **Private Notification Isolation**: `/users/{userId}/notifications/{notificationId}` can only be read (`get`/`list`), marked read (`isRead`, `updatedAt`), or deleted by `isOwner(userId)`. Senders can only create unread notifications tied atomically (`existsAfter`) to an active friend request or room invite when unblocked.
8. **Immutable Player Reports & Verified Account Self-Deletion**: `/playerReports/{reportId}` is append-only and readable only by its submitting reporter (`allow update, delete: if false`). Authenticated, email-verified owners may delete only their own account data and their own friendship/request/invite edges — never another user's private profile, privacy, block list, or notifications.

## 2. Adversarial Rejection Cases (All Expected: PERMISSION_DENIED)
1. **Cross-user profile or privacy read**: Player A calls `get(/users/playerB)` or `get(/users/playerB/privacy/settings)` -> DENIED.
2. **Self-awarding wins, stars, or unlocked levels**: Player A calls `update(/users/playerA, { matchesWon: 10 })`, `update(..., { levelStars: {'1': 3} })`, `update(..., { unlockedLevel: 8 })`, or `create` with non-zero stats -> DENIED.
3. **Stranger presence snooping**: Non-friend Player C calls `get(/users/playerA/presence/status)` -> DENIED.
4. **Unauthorized friend request accept/modify**: Sender (Player A) or third-party (Player C) modifies `friendRequests/playerA__playerB` -> DENIED; recipient accepting without reciprocal `/friends` batch -> DENIED.
5. **Blocked user friend request or room invite**: Blocked Player B creates `/friendRequests/playerB__playerA` or `/roomInvites/playerB__playerA` -> DENIED.
6. **Recipient privacy policy block**: Player C sends friend request when `friendRequestPolicy: 'nobody'`, or friend sends room invite when `roomInvitePolicy: 'nobody'` -> DENIED.
7. **Unrequested friend injection**: Player B creates `/users/playerA/friends/playerB` without an atomic pending->accepted request -> DENIED.
8. **Non-member multiplayer room access**: Uninvited Player C tries `get(/rooms/ROOM01)`, `get(/rooms/ROOM01/members/playerA)`, `create(/rooms/ROOM01/members/playerC)`, or `update(/rooms/ROOM01)` -> DENIED.
9. **Private notification snooping & spam**: Player B or C reads/lists/updates/deletes `/users/playerA/notifications/*`, or blocked/uninvited user creates a notification -> DENIED.
10. **Unauthorized account deletion**: Player A attempts to delete `/users/playerB`, `/users/playerB/blocked/playerA`, `/users/playerB/friends/playerC`, `/users/playerB/notifications/*`, `/playerDirectory/playerB`, or `/playerReports/*` -> DENIED.
11. **Shadow field & spoofed ID injection**: Adding `isAdmin: true` or spoofing `reporterUid`/`fromUid` -> DENIED.
12. **Client timestamp / unverified token write**: Writing without `request.time` or with `email_verified: false` -> DENIED.
